# 更新次数

## 业务口径

更新次数是去重后的上市事件数量。首次上市和后续上市均计为 1 次更新。

- 同一统计序列中的第一次上市计 1 次更新。
- 后续每个与已有上市日期不同的上市事件也计 1 次更新。
- 多个款型在同一品牌、同一车系、同一日期上市时，只计 1 次，不按款型数重复累计。
- 更新次数的年份取本次上市时间所在年份。
- 跨年更新整体计入本次上市年份，不按年份拆分。

## 与上市周期的关系

更新次数与 `measure:launch_cycle` 必须基于同一套去重后的上市事件集合，但两者对首次上市的处理不同：

```text
更新次数 = COUNT(全部去重上市事件)
平均上市周期 = 有效周期天数之和 / 有效周期记录数
```

首次上市计入更新次数，但其周期为空，不进入平均上市周期的分子和分母。更新次数与平均上市周期的有效周期数是两个不同指标，不得直接把更新次数作为平均周期分母。

图表中的“更新次数”和“平均上市周期”必须共享相同的基础事件集合、事件颗粒度、分组字段和年份归属规则，但聚合分母不同：柱状图统计全部上市事件，周期折线只对非空有效周期求平均。

当同一查询或图表还计算平均上市周期时，“先计算完整历史序列中的 `LAG`，后按本次上市年份筛选”是强制规则。年份条件只能用于最终的年度汇总，严禁放在 `LAG(launch_date)` 上游的数据集或 CTE 中，否则跨年周期会丢失上次上市事件。

## 统计颗粒度

默认按 `brand + serial_name + launch_date` 识别一个车系上市事件，并在 `brand + serial_name` 内形成时间序列。

当用户要求按传统能源、新能源或具体能源类型分组比较时，必须先按 `dimension:energy_type` 的业务映射确定当前款型的能源组，并按 `brand + serial_name + energy_group + launch_date` 去重，在 `brand + serial_name + energy_group` 内分别形成时间序列。

同一车系同一天在同一能源组内上市多个款型，只计一个事件。同一车系同一天同时存在传统能源和新能源款型时，可在两个能源组中各形成一个事件。

## 字段口径

与上市周期一致，从 `vehicle_params` 汇集完整明细：

- 品牌：`brand`。
- 车系：`serial_name`。
- 款型：`car_name`。
- 上市时间：`type_name = '上市时间'` 的 `type_value`。
- 能源类型：`type_name = '能源类型'` 的 `type_value`。

不得仅使用当前明细结果中的上市时间，也不得用款型名称中的年份代替真实上市日期。

## 计算规则

1. 按 `brand + serial_name + car_name` 汇总每个款型的有效上市日期和能源类型。
2. 根据查询是否按能源分组，构建默认车系序列或分能源组车系序列。
3. 对同一序列、同一上市日期去重。
4. 首次上市和后续上市事件全部保留，每个去重事件计 1 次。
5. 以本次上市日期年份作为更新年份。
6. 按用户要求的年份、能源组、品牌或车系统计事件数。

当更新次数与平均上市周期在同一查询或图表中计算时，必须先形成完整上市事件集合；平均周期再从该集合计算 `LAG(launch_date)`，之后按年份汇总。更新次数直接统计对应年份的全部去重事件。

## 聚合规则

- “更新次数”：`COUNT(*)`，统计全部去重上市事件，包括首次上市。
- “某年更新次数”：按本次上市日期年份分组或筛选后计数。
- “传统能源/新能源更新次数”：统计各能源组内的全部去重上市事件。
- 更新次数可以跨车系、品牌或能源组求和，但必须保持上市事件去重口径一致。

## 禁止规则

- 不要排除首次上市；首次上市必须计入更新次数。
- 不要按款型数量统计更新次数。
- 不要把同一车系同一天同一能源组的多个款型重复计数。
- 同时计算平均上市周期时，不要先按年份过滤再寻找上次上市事件。
- 不要使用款型名称中的年款推断上市年份。
- 不要让“更新次数”和同图中的“平均上市周期”使用不同事件序列。
- 不要把更新次数作为平均上市周期的分母；平均周期分母必须是非空有效周期记录数。
