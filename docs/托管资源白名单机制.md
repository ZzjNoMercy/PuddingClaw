# PuddingClaw 托管资源白名单机制

> 日期：2026-07-02  
> 状态：当前实现说明  
> 关联：权限机制、知识库、聊天附件、image_analyzer

## 一句话原则

不在 `/workspace/` 的路径默认是外部文件，需要授权；但由用户在 PuddingClaw 中显式配置或上传的资源，属于 PuddingClaw 托管资源，不再弹外部文件授权。

## 当前白名单

| 类型 | 形式 | 说明 |
|---|---|---|
| 项目工作区 | `/workspace/...` | 当前项目文件，走 DeepAgents 文件工具 |
| 知识库虚拟路径 | `/knowledge/...` | 用户配置的知识库目录，走 DeepAgents 文件工具或 LlamaIndex |
| 知识库物理路径 | `/Users/.../knowledge/...` | 主要用于图片资产，比如 MinerU 提取图 |
| 聊天附件 ID | `att_xxx` | 用户在聊天框上传或粘贴的附件 |
| 聊天附件物理路径 | `backend/data/attachments/{session_id}/{att_xxx}/...` | 附件落盘后的真实文件路径 |

## 代码入口

- `backend/graph/managed_paths.py`
  - `is_managed_resource_path(path, base_dir)`
  - 统一判断知识库目录和附件目录。
- `backend/graph/attachment_store.py`
  - `attachment_store.root_dir`
  - 附件根目录：`backend/data/attachments`。
- `backend/tools/read_resource_tool.py`
  - 读取 `att_xxx`。
  - 图片路径在知识库或附件目录下时，不需要外部授权。
- `backend/tools/read_external_file_tool.py`
  - 如果传入的是托管资源物理路径，直接读取。
  - 如果不是托管资源，继续走 `external_file_read` 授权。
- `backend/graph/deepagents_manager.py`
  - image analyzer 读取本地图片时，允许 workspace / knowledge / attachments 下的图片。

## 和知识库的关系

用户在设置中选择的知识库目录，会挂载成：

```text
/knowledge/
```

导入后的主内容默认放：

```text
/knowledge/imported/日期/
```

MinerU 提取的图片通常放：

```text
/knowledge/assets/日期/任务ID/
```

这些都属于知识库托管资源。

## 和聊天附件的关系

聊天框上传文件不会自动进入知识库。它会先落盘为 session 附件：

```text
backend/data/attachments/{session_id}/{att_xxx}/...
```

Agent 应优先用：

```text
read_resource(resource="att_xxx")
```

如果工具链拿到了附件物理路径，也视为托管资源，不需要再次授权。

## 仍需授权的情况

下面这些仍是外部文件：

```text
/Users/pet/Downloads/foo.pdf
/Users/pet/Desktop/image.png
/tmp/random-file.txt
```

除非它们位于用户配置的 knowledge 目录，或位于 PuddingClaw 附件目录，否则必须进入 `external_file_read` 授权。

## 设计边界

- 白名单不是“允许 Agent 读整个电脑”。
- 白名单只覆盖用户已配置的 knowledge 目录和用户已上传的附件。
- 外部路径授权仍按 session 保存，可撤销。
- 图片内容不能只靠文件名猜；需要 `read_resource` 后交给 `image_analyzer`。
