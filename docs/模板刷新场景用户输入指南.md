# 模板刷新场景用户输入指南

## 1. 这份指南解决什么问题

“刷新模板”是指保留现有模板的结构和风格，用新的数据、文字、图表或图片生成一份新版本。模板可以是 HTML、PPT、仪表盘、周报、月报、经营分析报告、邮件或其他结构化内容。

为了让系统正确刷新模板，用户不需要描述实现代码，但需要说明“更新什么、依据什么更新、哪些不能改、怎样算完成”。信息越完整，结果越稳定；信息不足时，系统应先确认关键口径，不能直接沿用模板中的示例内容。

## 2. 最少需要提供的信息

一次可执行的模板刷新请求，至少应包含以下六项：

1. **模板**：需要刷新的原始文件或模板名称。
2. **目标**：这次刷新是为了生成什么报告或页面。
3. **数据**：数据来源、文件、数据库或接口。
4. **范围**：时间、业务对象、地区、组织、产品等筛选范围。
5. **口径**：核心指标如何计算，按什么对象统计。
6. **输出**：输出格式、保存位置和是否覆盖原文件。

可直接使用下面的最简表达：

> 请使用【模板】，基于【数据源】生成【报告名称】。统计范围是【时间和业务范围】，核心指标按【统计口径】计算。保留【不能修改的内容】，更新【需要修改的内容】，最后输出为【文件格式和名称】。

## 3. 建议补充的十二类信息

### 3.1 刷新目标

说明这次刷新要达到什么结果。

建议提供：

- 报告或页面名称。
- 使用场景，例如管理汇报、客户交付、内部复盘、运营监控。
- 目标读者，例如高管、业务团队、销售、客户、公众。
- 期望用户看完后得到的核心结论或采取的行动。

示例：

> 生成 6 月经营月报，供管理层复盘区域表现和识别异常市场。

### 3.2 模板及修改边界

说明哪些内容是固定模板，哪些允许刷新。

建议提供：

- 原始模板文件。
- 必须保留的页面、章节、布局、品牌元素和交互。
- 允许新增、删除或合并的内容。
- 是否允许调整图表类型、颜色、字号和排版。
- 是否允许修改模板源码。
- 是否保留原文件，还是直接覆盖。

常见修改范围：

| 范围 | 典型内容 |
| --- | --- |
| 只更新数据 | 数字、表格、图表序列 |
| 更新数据与文案 | 标题、摘要、结论、注释 |
| 更新全部内容 | 数据、文案、图片、章节、图表 |
| 只调整样式 | 颜色、字体、间距、布局 |

### 3.3 数据来源

说明新内容从哪里获得。

建议提供：

- 文件、数据库、数据集、接口或网页地址。
- 数据表、工作表或接口名称。
- 数据更新时间和截止日期。
- 多个数据源之间的关联字段。
- 数据访问权限或需要用户上传的文件。
- 哪个数据源是最终可信来源。

如果有多个来源，应明确优先级：

> 优先使用正式数据库；数据库缺失时使用业务台账；模板示例值不得作为数据来源。

### 3.4 时间范围

时间是模板刷新最容易产生误解的维度之一。

建议提供：

- 统计开始时间和结束时间。
- 数据截止日期。
- 时间颗粒度：日、周、月、季度、年。
- 同比、环比或基期。
- 不完整周期是否纳入。
- 使用自然周期还是业务周期。
- 时区和财务年度定义。

示例：

> 统计 2026 年 1–6 月，按自然月展示；同比比较 2025 年同期；6 月数据不完整时标注“截至 6 月 25 日”。

### 3.5 分析对象与统计颗粒度

统计颗粒度决定“一条记录代表什么”，必须明确。

常见颗粒度包括：

- 用户、客户、订单、商品、设备、项目。
- 门店、城市、区域、部门、公司。
- 日、周、月、季度、年度。
- 事件、版本、批次、合同、工单。

建议说明：

- 默认统计对象。
- 唯一标识字段或组合键。
- 去重规则。
- 上卷和下钻层级。
- 同名对象如何区分。

示例：

> 订单数按订单 ID 去重；客户数按客户 ID 去重；不能按客户名称去重。

### 3.6 分析维度

维度用于筛选、分组和比较。用户不必一次列出所有字段，但应提供业务上必须保留的维度。

常见维度类别：

| 类别 | 示例 |
| --- | --- |
| 时间 | 日期、周、月份、季度、年度 |
| 组织 | 公司、事业部、部门、团队、人员 |
| 地理 | 国家、省、市、区域、门店 |
| 客户 | 客户类型、行业、等级、生命周期 |
| 产品 | 品类、品牌、系列、型号、版本 |
| 渠道 | 直营、经销、电商、活动、来源 |
| 状态 | 新增、进行中、完成、取消、异常 |
| 价格 | 价格带、折扣区间、客单价区间 |
| 行为 | 访问、咨询、下单、支付、复购 |

对每个关键维度，建议补充：

- 字段来源。
- 允许值或分组规则。
- 未知值如何处理。
- 是否允许多选。
- 是否需要显示“其他”。
- 是否存在业务别名或映射表。

### 3.7 度量值和计算口径

度量值是需要计算或展示的数字。只给指标名称通常不够，还应说明公式和适用范围。

每个核心指标建议包含：

| 项目 | 说明 |
| --- | --- |
| 指标名称 | 页面上显示的名称 |
| 业务含义 | 指标用于回答什么问题 |
| 公式 | 分子、分母、聚合方式 |
| 单位 | 元、万元、个、次、天、百分比等 |
| 颗粒度 | 按用户、订单、商品或其他对象统计 |
| 筛选条件 | 纳入和排除哪些数据 |
| 时间口径 | 发生时间、创建时间、完成时间等 |
| 空值规则 | 空值、零值和未知值如何处理 |
| 精度 | 小数位和四舍五入规则 |

示例：

> 转化率 = 完成支付的唯一订单数 ÷ 创建的有效订单数；取消订单不进入分子和分母；保留一位小数。

### 3.8 内容结构

说明模板中的哪些内容必须存在。

常见内容模块：

- 标题和报告日期。
- 执行摘要。
- 核心指标卡片。
- 趋势分析。
- 分类对比。
- 排名或明细表。
- 异常和风险提示。
- 结论与建议。
- 数据口径和来源说明。

建议说明：

- 必需模块和可选模块。
- 模块顺序能否调整。
- 没有数据时保留模块还是隐藏模块。
- 文案语气和长度。
- 是否需要自动生成结论和建议。

### 3.9 图表要求

如果模板包含图表，建议补充：

- 图表要回答的问题。
- 横轴、纵轴、系列和单位。
- 图表类型是否固定。
- 排序规则。
- 是否展示数据标签。
- 是否需要同比、环比、目标线或参考线。
- 是否允许使用双轴。
- 空数据和数据量过大时如何展示。
- 图表是否需要交互、筛选、下载或打印。

不必指定图表类型时，可以描述业务意图：

> 需要看趋势、结构变化、对象对比和异常点，图表类型由系统选择。

### 3.10 文字与结论生成规则

自动生成结论时，需要说明系统可以做多大程度的判断。

建议提供：

- 是否只描述事实，还是允许给出原因推断和建议。
- 结论数量和长度。
- 是否需要引用具体数据。
- 重要变化的判断阈值。
- 正负变化的业务含义。
- 禁止使用的措辞。
- 是否需要风险提示或免责声明。

推荐规则：

> 每条结论必须引用至少一个指标或图表；数据只能证明相关性时，不得写成因果关系。

### 3.11 样式与品牌规范

如果样式不能完全沿用模板，应提供：

- 品牌名称、Logo 和标准色。
- 字体要求。
- 页面尺寸或屏幕尺寸。
- 深色或浅色主题。
- 图表配色规则。
- 图片、图标和插画风格。
- 打印和导出要求。
- 无障碍要求，例如对比度和替代文本。

### 3.12 输出与验收

明确交付物和“怎样才算完成”。

建议提供：

- 输出格式：HTML、PPTX、PDF、图片或其他格式。
- 文件名称和保存位置。
- 是否要求单文件、离线打开或自包含依赖。
- 是否保留可编辑状态。
- 是否需要移动端适配。
- 是否需要浏览器、打印或投屏验证。
- 是否需要同时提供数据文件或计算明细。

通用验收项：

- 模板规定的必需模块全部存在。
- 所有示例数据已替换或明确标记为空。
- 数字、单位、时间范围和口径一致。
- 图表与正文引用同一数据结果。
- 页面不存在未解析变量或运行错误。
- 输出文件可正常打开、打印或导出。

## 4. 数据缺失和异常处理

用户最好提前说明以下情况如何处理：

- 某个字段完全缺失。
- 某个周期数据不完整。
- 指标分母为零。
- 不同数据源结果冲突。
- 存在重复记录。
- 存在异常大值、负值或非法日期。
- 某个章节没有足够数据。

如果用户没有指定，推荐默认规则：

1. 不使用模板示例值填补缺失数据。
2. 不擅自用零代替未知值。
3. 保留必需模块并显示缺失原因。
4. 对异常数据先报告，不静默删除。
5. 多数据源冲突时使用用户指定的权威来源；未指定时请求确认。

## 5. 哪些信息必须追问

以下信息缺失时，系统通常应先追问，而不是自行假设：

- 不知道使用哪个模板或数据源。
- 不知道统计时间范围。
- 不知道核心指标的分子、分母或去重对象。
- 不知道是覆盖原文件还是生成新文件。
- 多个数据源冲突且没有权威来源。
- 用户要求自动结论，但没有说明允许事实描述还是原因推断。
- 不同选择会显著改变最终结果或业务含义。

以下信息通常可以使用默认值，但应在结果中说明：

- 文件名称。
- 小数位数。
- 图表的具体视觉类型。
- 非核心模块的排序。
- 页面微小的间距和字号调整。

## 6. 推荐的刷新方式

为了避免模板内出现新旧数据混杂，推荐采用以下流程：

1. 读取模板并识别固定结构、可刷新字段和图表。
2. 根据用户输入生成刷新计划。
3. 完成全部数据查询和计算。
4. 将结果整理成统一的结构化数据包。
5. 校验字段、口径、数组长度、单位和必需模块。
6. 复制原模板生成新文件。
7. 一次性刷新文字、数字、表格、图片和图表。
8. 打开输出文件进行页面和运行时检查。
9. 交付新文件，并说明数据范围、缺失项和默认假设。

不推荐：

- 边查询边修改模板。
- 直接搜索并替换页面中的数字。
- 把模板示例值当作数据兜底。
- 只刷新图表但不更新正文结论。
- 在没有确认统计口径时计算比例指标。

## 8. 简洁版需求模板

如果刷新任务比较简单，可以只填写下面的内容：

```markdown
请使用【模板文件】生成【报告名称】。

- 数据来源：【文件/数据表/接口】
- 数据截止日期：【日期】
- 统计范围：【时间、对象、地区、组织或产品范围】
- 统计颗粒度：【一条记录代表什么，如何去重】
- 核心指标：【指标及计算口径】
- 必须保留：【章节、布局、图表、品牌元素】
- 需要更新：【数据、文案、表格、图片、图表】
- 缺失数据处理：【保留并说明 / 隐藏 / 请求确认】
- 输出要求：【格式、文件名、保存位置】
```
