# 分析模型一句话刷新完整报告：终极形态开发方案

## 1. 文档状态

- 状态：方案草案，暂不实施
- 当前阶段：验证产品配置分析所需的维度、度量值和计算口径
- 开发启动条件：关键语义资产完成测试并达到本文定义的准入标准
- 首个验证场景：产品配置分析月度报告刷新
- 长期目标：形成可复用于其他分析模型和报告模板的通用能力

## 2. 背景

复杂分析报告通常包含多个章节、指标卡、表格、图表、结论和数据口径。传统生成方式要求用户反复指定数据范围、计算规则、页面结构和输出要求，使用成本高，也容易产生口径不一致、模板示例值残留或部分模块漏刷的问题。

目标形态是把稳定的业务知识、统计口径和报告结构沉淀到分析模型中。最终用户只需要表达业务意图，例如：

> 刷新 6 月的产品配置分析报告。

Agent 自动完成模型选择、时间解析、任务规划、数据计算、报告刷新、页面校验和文件交付。

## 3. 最终用户体验

### 3.1 标准请求

```text
用户：刷新 6 月的产品配置分析报告。
```

### 3.2 Agent 自动完成

1. 识别并加载“产品配置分析”模型。
2. 根据会话时间和模型默认规则解析“6 月”的年份及日期范围。
3. 读取模型绑定的维度、度量值、颗粒度、关系和约束规则。
4. 读取默认报告模板和报告生成 reference。
5. 从模板编译完整的报告任务图。
6. 执行全部查询、计算和证据整理。
7. 生成统一的报告数据包。
8. 校验报告数据包的完整性和口径一致性。
9. 复制基准模板并一次性刷新全部内容。
10. 在浏览器中验证章节、表格、图表和运行时状态。
11. 交付报告文件，并说明数据截止日、缺失项和异常。

### 3.3 理想回复

```text
6 月产品配置分析报告已生成。

- 数据截止日期：2026-06-30
- 完成章节：7/7
- 完成图表：24/24
- 数据覆盖不足：2 项，已在数据口径章节说明
- 页面运行时检查：通过
```

## 4. 设计原则

### 4.1 一句话触发，模型承担复杂度

成熟分析模型应保存稳定默认值，避免要求最终用户每次填写完整需求表。用户只表达本次变化，例如月份、品牌、区域或报告范围。

### 4.2 模板定义输出，语义资产定义计算

- HTML/PPT 模板定义章节、字段、表格、图表和视觉约束。
- 维度、度量值和颗粒度定义业务语义及计算口径。
- Reference 定义生成流程、缺失处理和质量标准。
- Agent 将三者编译为可执行任务图。

不得从模板示例数字推断业务口径，也不得把图表配置当作度量值计算逻辑。

### 4.3 先完成计算，再刷新模板

禁止边查询边修改报告。所有查询和计算完成后，先生成统一数据包并通过校验，再一次性刷新模板，避免新旧数据混杂。

### 4.4 结果必须可追溯

每个指标、表格、图表和结论都应能追溯到：

- 使用的维度和度量值。
- 数据源和查询任务。
- 筛选范围和统计颗粒度。
- 分子、分母及派生公式。
- 数据截止日期。

### 4.5 长任务必须可恢复

章节多、查询多、渲染时间长时，Agent 应保存任务状态和中间结果。中断后从最近检查点继续，不能重复已成功的查询，也不能丢失已确认的口径。

## 5. 分析模型需要封装的内容

### 5.1 语义资产

- 维度。
- 度量值。
- 分析颗粒度。
- 数据资产关系。
- 实体解析和跨源映射。
- SQL 或计算约束。

### 5.2 报告模板

- 默认 HTML/PPT 模板。
- 必需章节和顺序。
- 可刷新字段和字段路径。
- 表格列及排序规则。
- 图表容器、图表类型和数据契约。
- 空数据状态。
- 打印、导出和响应式要求。

### 5.3 报告生成 Reference

- 用户输入解析规则。
- 模板到任务图的编译规则。
- 必需任务和依赖关系。
- 数据查询及计算顺序。
- 缺失数据和异常处理。
- 报告数据包结构。
- 渲染流程。
- 四阶段质量 Gate。

### 5.4 默认策略

模型应预置：

- 默认市场和业务范围。
- 默认时间解释方式。
- 默认数据截止日期规则。
- 默认纳入和排除规则。
- 默认统计颗粒度。
- 默认输出文件名和保存位置。
- 默认缺失数据处理方式。
- 默认结论生成边界。

## 6. Agent 运行架构

```text
用户请求
  ↓
意图与分析模型路由
  ↓
模型上下文加载
  ├─ 数据资产
  ├─ 维度/度量值/颗粒度
  ├─ 关系与 Guardrails
  ├─ 默认模板
  └─ 报告生成 Reference
  ↓
模板解析与任务编译
  ↓
长任务执行器
  ├─ 查询计划
  ├─ 共享分母/基础数据集
  ├─ 章节计算任务
  ├─ 证据与结论任务
  └─ 检查点
  ↓
统一 Report Payload
  ↓
Payload 校验器
  ↓
确定性模板渲染器
  ↓
浏览器/文件验收器
  ↓
报告交付
```

## 7. 模板解析与任务编译

### 7.1 Agent 应自动识别

- 报告标题、日期和数据截止日。
- 章节结构、顺序和必需状态。
- 指标卡及其字段路径。
- 表格及其列、排序和颗粒度。
- 图表 DOM ID、类型、系列、单位和轴。
- 模板变量和数据绑定。
- 图片、图标及其他媒体资源。
- 交互、筛选、打印和导出功能。

### 7.2 任务节点示例

```json
{
  "task_id": "chart.example_trend",
  "section": "example_section",
  "target": "#exampleTrendChart",
  "output_path": "charts.example.trend",
  "dimensions": ["month", "category"],
  "measures": ["example_rate"],
  "grain": ["month", "category"],
  "filters": {},
  "dependencies": ["dataset.valid_objects"],
  "empty_state": "保留图表并显示数据不足原因",
  "status": "pending"
}
```

### 7.3 任务图必须覆盖

- 所有必需章节。
- 所有指标卡。
- 所有图表和表格。
- 执行摘要和结论。
- 数据口径及异常说明。
- 页面渲染和验收任务。

## 8. Agent 执行状态机

```text
S0 接收请求
  → S1 选择分析模型并解析参数
  → S2 加载语义资产、模板和 Reference
  → S3 编译报告任务图
  → Gate 1：计划完整性
  → S4 执行查询和计算
  → Gate 2：计算可审计性
  → S5 生成 Report Payload
  → Gate 3：Payload 完整性
  → S6 渲染报告
  → S7 浏览器/文件验收
  → Gate 4：交付质量
  → S8 交付
```

任何 Gate 失败时，应返回上一阶段修复。不可跳过失败项后把任务标记为完成。

## 9. 统一 Report Payload

### 9.1 建议结构

```json
{
  "schema_version": "1.0",
  "request": {
    "original_text": "刷新 6 月的产品配置分析报告",
    "resolved_period": {},
    "model_id": "产品配置分析"
  },
  "report": {
    "metadata": {},
    "scope": {},
    "metrics": {},
    "sections": {},
    "tables": {},
    "methodology": {}
  },
  "charts": {},
  "evidence": {},
  "execution": {
    "plan_tasks": 0,
    "completed_tasks": 0,
    "checkpoints": [],
    "warnings": [],
    "missing_tasks": []
  }
}
```

### 9.2 数据包职责

- `request`：保存用户原始请求和 Agent 解析后的参数。
- `report`：保存文字、数字、章节和表格内容。
- `charts`：保存图表需要的类别、系列和数值。
- `evidence`：保存查询、数据范围、口径和结果来源。
- `execution`：保存长任务计划、完成情况和检查点。

### 9.3 禁止项

- 不得在 Payload 中保留基准模板示例值。
- 不得把无法追溯来源的手填数组写入图表数据。
- 不得把 HTML 片段作为业务指标的唯一载体。
- 不得在图表渲染阶段重新计算业务度量值。

## 10. 确定性模板渲染

模板渲染器负责展示，不负责业务计算。

推荐流程：

1. 复制基准模板生成新文件。
2. 校验 Payload schema 和模板版本。
3. 根据字段路径更新标题、日期、指标卡和正文。
4. 根据结构化数据重建表格。
5. 将图表数据传给图表运行时。
6. 销毁旧图表实例并重新创建。
7. 为无数据模块生成统一空状态。
8. 写入渲染时间、模板版本和 Payload 摘要。

禁止使用正则逐个替换模板中的数字，也不得直接修改基准模板的数据数组。

## 11. 四个质量 Gate

### Gate 1：计划完整性

- 必需章节、图表、表格和指标卡全部进入任务图。
- 每个任务都有维度、度量值、颗粒度、输出路径和空数据策略。
- 任务依赖关系无循环且可执行。

### Gate 2：计算可审计性

- 每个指标都能定位到已测试的语义资产或明确派生规则。
- 比率指标包含分子、分母和统计颗粒度。
- 查询结果保存数据范围、行数、异常和来源。
- 每条自动结论至少引用一个证据节点。

### Gate 3：Payload 完整性

- 必需字段存在且类型正确。
- 图表 categories 和 series 长度一致。
- 数值范围、单位、精度和日期合法。
- 计划任务完成数与实际完成数一致。
- 缺失数据使用明确状态，不使用模板示例值填充。

### Gate 4：交付质量

- 所有必需章节正常显示。
- 有数据图表全部完成渲染。
- 无数据模块显示明确原因。
- 页面不存在未解析模板变量。
- 图表与正文使用同一批计算结果。
- 浏览器控制台无运行时错误。
- 文件可正常打开、打印或导出。

## 12. 长任务状态与恢复

### 12.1 检查点

建议至少保存以下检查点：

- 模型和参数解析完成。
- 报告任务图生成完成。
- 共用基础数据集完成。
- 每个章节计算完成。
- Payload 生成并校验完成。
- HTML 渲染完成。
- 页面验收完成。

### 12.2 恢复规则

- 已成功且输入未变化的查询不重复执行。
- 失败任务可以单独重试。
- 上游结果变化时，只使其下游任务失效。
- 用户修改统计范围后，应生成新计划版本。
- 恢复后必须重新执行后续 Gate。

### 12.3 幂等性

同一模型版本、模板版本、数据截止日和请求参数应生成相同的核心指标和图表数据。输出文件名可以包含运行时间，但业务结果不能因重试发生无解释变化。

## 13. 需要追问的边界

成熟模型应尽量使用默认值，但以下情况必须追问：

- 月份对应年份无法可靠确定。
- 用户请求超出模型支持范围。
- 必需维度或度量值缺失。
- 多个统计口径会显著改变结果。
- 数据源不可访问或权威来源冲突。
- 关键数据覆盖不足且无法合理降级。
- 用户要求覆盖基准模板或其他不可逆操作。

其他非关键问题，如输出文件名、小数位、微小版式调整，可使用模型默认值并在交付说明中披露。

## 14. 开发启动前置条件

本方案暂不进入实现。必须先完成产品配置分析语义资产验证。

### 14.1 维度准入标准

- 业务定义清楚。
- 数据字段映射稳定。
- 枚举和标准化规则完成。
- 未知值及异常值处理明确。
- 可与目标数据资产正确关联。
- 常见筛选和分组查询测试通过。

### 14.2 度量值准入标准

- 业务含义、分子、分母和单位明确。
- 统计颗粒度和去重键明确。
- 时间归属规则明确。
- 纳入与排除条件明确。
- 空值、分母为零和异常值规则明确。
- 基准 SQL 或确定性计算实现已验证。
- 使用代表性数据完成正确性测试。
- 多维切片后口径保持一致。

### 14.3 语义资产覆盖检查

开发启动前，应使用目标报告模板生成一次“语义覆盖清单”：

- 模板需要哪些维度。
- 模板需要哪些度量值。
- 哪些已测试通过。
- 哪些缺失或仍不稳定。
- 哪些只能作为派生指标。
- 哪些图表暂时无法可靠计算。

只有必需任务的语义资产覆盖达到 100%，或已有明确可接受的空数据策略，才进入终极形态开发。

## 15. 后续开发阶段

### 阶段 A：模型与模板契约

- 固化模型默认值。
- 完成模板机器可读标记。
- 定义 Report Payload schema。
- 定义模板版本和 Payload 版本兼容规则。

### 阶段 B：模板解析与任务编译

- 实现 HTML 模板结构解析。
- 自动识别章节、字段、表格和图表。
- 生成任务图及依赖关系。
- 实现 Gate 1。

### 阶段 C：长任务执行

- 接入维度和度量值查询。
- 支持共享基础数据集。
- 保存证据、中间结果和检查点。
- 支持失败重试和断点恢复。
- 实现 Gate 2。

### 阶段 D：Payload 与渲染

- 实现 Payload 生成器和校验器。
- 实现文本、表格和图表统一绑定。
- 实现确定性 HTML 渲染。
- 实现 Gate 3。

### 阶段 E：浏览器验收与交付

- 检查章节和模板变量。
- 检查图表实例及运行时错误。
- 检查打印和导出。
- 生成交付摘要。
- 实现 Gate 4。

### 阶段 F：通用化

- 从产品配置分析中抽取通用模板协议。
- 支持其他分析模型注册模板。
- 支持不同模板拥有不同章节和图表任务。
- 建立通用的模板刷新用户体验和运维指标。

## 16. 首个端到端测试用例

### 16.1 标准用例

```text
刷新 6 月的产品配置分析报告。
```

验证：

- 一句话能否正确路由到分析模型。
- 时间参数能否正确解析。
- 模板任务图是否完整。
- 全部指标和图表能否计算并渲染。
- 最终报告是否无示例数据残留。

### 16.2 数据缺失用例

人为移除一个非核心配置字段，验证：

- Agent 是否识别覆盖不足。
- 是否使用空状态而不是模板示例值。
- 是否在口径章节和交付摘要中说明。

### 16.3 中断恢复用例

在完成部分章节后中断任务，验证：

- 是否保存检查点。
- 是否只继续未完成任务。
- 是否避免重复已完成查询。
- 恢复后是否重新通过 Gate。

### 16.4 口径冲突用例

提供会改变核心结果的两种统计口径，验证 Agent 是否暂停并请求用户选择，而不是自行猜测。

## 17. 成功指标

### 17.1 正确性

- 必需任务完成率：100%。
- 语义资产引用正确率：100%。
- 指标与图表一致率：100%。
- 模板示例数据残留率：0%。
- 未解析模板变量：0。

### 17.2 健壮性

- 非关键数据缺失时可降级完成。
- 单个查询失败后可重试。
- 中断后可从检查点恢复。
- 重试不会重复修改基准模板。
- 同一输入重复运行的业务结果一致。

### 17.3 用户体验

- 标准场景只需一句话触发。
- 非必要问题不追问。
- 交付时明确说明数据截止日和异常。
- 输出文件可直接查看、打印或导出。

## 18. 当前已有基础

目前已经具备以下设计和验证材料：

- 产品配置分析 HTML 报告模板。
- ECharts 图表实现。
- 产品配置分析模型定义。
- 报告生成 Reference 初稿。
- 通用模板刷新用户输入指南。

现有材料用于验证方向，不代表终极形态已经实现。当前 HTML 中仍存在示例数据和局部绑定能力，后续需要通过统一 Payload 与确定性渲染器完成改造。

## 19. 当前决策

1. 先停止终极形态的工程实现。
2. 优先测试并完善产品配置分析相关维度和度量值。
3. 维度和度量值达到准入标准后，重新进行模板语义覆盖检查。
4. 覆盖检查通过后，按本文阶段 A–F 开始开发。
5. 首先完成产品配置分析端到端用例，再抽取通用能力。
